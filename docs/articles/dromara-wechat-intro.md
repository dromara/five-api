# 轻量的企业级 Token 网关，应该是怎么样的

> 轻量的企业级 Token 方案。把 AI 额度发给部门和个人，一条命令自己托管。同一台机器实测，吞吐比 new-api 高约 15%，是 LiteLLM 的 1.8 倍。MIT 许可，没有企业版。

公司要给几十个部门、一批固定客户发 AI Token。人不能混用一把 Key，额度要分开，离职了要能查他发过什么，Claude Code 和 Codex 也得走同一套额度。

公开中转站是用户自己注册、自己充值，人管不住。完整的企业网关要接一百多家供应商，还得配 SSO 和组织架构，一套下来像上了中台。Five API 卡在中间：企业级的 Token 治理，轻到一条命令能跑起来。

## 项目简介

Five API 是自托管的多租户 AI 网关。上游接 OpenAI、Claude、Gemini、DeepSeek、通义千问。平台开户、分额度、管渠道；租户只管理自己的 Key，花不了别人的额度。

租户是部门、团队、项目，也可以是你的客户。平台管理员和租户两种角色。

## 轻，但跑得比它们快

轻量常被理解成「功能少、性能凑合」。我们把 new-api、LiteLLM 和 Five API 装在同一台 8 核机器上，接同一个模拟上游，用同一个压测程序，三家都开着按 Key 记账，跑了三轮：

| 每分钟处理请求（连后台写账一起算） | 满载时延迟中位数 |
|---|---|
| **Five API：4.7–5.3 万次** | **约 50 毫秒** |
| new-api：4.3–4.5 万次 | 约 85 毫秒 |
| LiteLLM：2.8 万次 | 约 115 毫秒 |

吞吐比 new-api 高约 15%，是 LiteLLM 的 1.8 倍；同样压力下，请求等待的时间只有 new-api 的一半左右。

计时不是到响应返回就停，而是等每一笔花费都写进数据库才停，后台慢慢补账的时间也算在内。只看响应速度，Five API 每分钟能到 6 万次，几十个租户合用和单个租户一样快，不会因为同一个账户请求多就排队。

快在两处：

- **记账不挡路**。请求只看余额够不够，不锁数据库。花费先进 Redis 队列，后台每半秒整批写入，一批几百笔只提交一次。写失败整批退回重写，按请求号去重，不漏记、不重复扣。
- **多进程吃满 CPU**。默认按核数启动进程，多台网关共用同一套 MySQL 和 Redis，加机器就能扩。

接真实 DeepSeek 时，首字只比直连慢 6 到 19 毫秒，用户感觉不到中间多了一层。

原始数据和重跑脚本都在仓库的 `docs/BENCHMARK.md`，谁都可以照着复现。

## 企业级 Token，轻在哪

### 谁能用、用多少，平台说了算

平台创建租户账号，分配美元额度、可用模型，以及共享的 RPM、TPM 和并发。租户自己建 Key、设 IP 白名单、停用和撤销。账号归属创建后不能改。租户看不到别人的 Key，也看不到上游地址和密钥。

Key 明文只显示一次。撤销之后用量还在，不能靠删掉 Key 把记录抹掉。

![租户管理](../images/tenants.png)

### 额度按人和时间切开

租户和 Key 两层限额。额度、RPM、TPM、并发都能限，再加 5 小时、1 天、7 天的滚动限额，额度按月重置。

给团队开编码助手，可以做成「每月 100 美元，每 5 小时最多 10 美元」。额度快见底，自动降到便宜模型。成本按天看缓存命中和省下的钱。这些都在开源版里。

![成本洞察](../images/insights.png)

### 发过什么，查得到

按 Key 保存请求内容（不存回复），私钥、AWS、GitHub 这些密钥实时替换成标记。人要离职，或者怀疑泄密，选中 Key，让便宜模型把最近的请求逐条审一遍，报告能下载。

new-api 不存请求内容。LiteLLM 的密钥检测在企业版。Five API 开源版就带。

![审计报告](../images/audit.png)

### 渠道和模型归平台管

同一个模型可以走多条渠道，按实际服务的渠道计价，也可以给单个模型锁一口价。Key 可以限定只走某几个渠道。上游报错、超时、限流自动换渠道，流式只在首包之前换。

定时探活。每天用固定题目看 GPT、Claude 是不是降智了。这是参考信号，不会因为一道题失败就停掉渠道。

### 编码工具直接接

OpenAI 和 Anthropic 两套协议原样透传，不做协议互转。工具调用、流式事件、缓存字段和上游一致。Claude Code 2.1.197、Codex 0.164.0 用真实渠道测过。改个地址，团队的 Agent 就走公司发的 Token，也走公司的审计。

记账各家网关都有，这里不展开。默认先放行、花费后台批量入库；余额一分都不能超的场景，切成严格模式，请求发出前按额度预占。没配价格的模型不放行。真实 DeepSeek 渠道 320 笔流式请求逐笔重算，没有对不上的。

## 和 new-api、LiteLLM 放一起看

| | Five API | new-api | LiteLLM |
|---|---|---|---|
| 定位 | 轻量企业 Token：开户、分额度、审计 | 公开中转站，自助注册、在线充值 | 企业统一出口，100+ 供应商 |
| 同机吞吐（次/分钟） | **4.7–5.3 万** | 4.3–4.5 万 | 2.8 万 |
| 满载延迟中位数 | **约 50 毫秒** | 约 85 毫秒 | 约 115 毫秒 |
| 租户自管 Key、IP 白名单 | 开源版包含 | 支持 | 企业版 |
| 请求审计 | 保存内容，密钥扫描，AI 审查 | 不保存请求内容 | 可保存；密钥检测属企业版 |
| 余额管控 | 默认先放行、批量记账；可切严格模式足额预占 | 只预扣输入；余额超 10 美元跳过 | 先放行，依赖 Redis |
| 未配置价格 | 拒绝 | 返回价格错误 | 放行，按 0 记账 |
| 模型质量检测 | 健康检测 + 降智参考 | 连通性 | 连通性 |

功能项依据 2026 年 10 月的公开文档；性能为 2026 年 11 月同机实测，三家均为默认配置。

怎么选，看你要发 Token 给谁：

- 选 Five API：用户是固定的部门、团队或一批客户。你来开户、分额度、做审计，又不想为了组织架构上一套中台，还要扛得住整个公司的调用量。一条命令部署，多台网关共用同一套 MySQL 和 Redis。
- 选 new-api：要做面向公众的中转站，用户自己注册、在线充值、用兑换码。
- 选 LiteLLM：要接 Bedrock、Vertex 等一百多家供应商，或者协议之间要互转。

## 快速开始

后端 FastAPI + MySQL + Redis，前端 Vue 3 + Element Plus，一条命令部署：

```bash
git clone https://gitee.com/dromara/five-api.git
cd five-api
./service.sh deploy
```

打开 `http://服务器IP:8080`，用 admin / admin123 登录，首次登录要改密码。已有代码只需把 OpenAI 或 Anthropic SDK 的地址换成网关地址。开户、分额度、审计都在开源版里。
