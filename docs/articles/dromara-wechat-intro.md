# 轻量的企业级 Token 网关，应该是怎么样的

> 轻量部署，同机实测性能领先，额度、计费、审计和泄密防护全部开源。

AI 真正进入团队后，难点不再是接通一个模型，而是把几十个部门、上百把 Key 和每一笔费用长期管清楚：

**额度怎么分？成本怎么算？渠道怎么切？敏感数据怎么查？**

那么，一个轻量的企业级 Token 网关，应该是什么样？

我们的答案是：**部署要轻，调用要快，账目要清楚，安全能力要完整，接入还不能折腾。**

Five API 就是按这个思路做的。平台接入 OpenAI、Claude、Gemini、DeepSeek、通义千问等上游，再按租户发放额度和 Token。业务照常调用模型，预算、计费、路由和审计交给网关。

---

## 01 轻量，首先要部署简单

轻量不只是少占一点内存，更重要的是部署、使用和扩容都足够直接：

**部署轻：** 一条命令启动，只依赖 MySQL 和 Redis。

**使用轻：** 创建账号、设置额度、发放 Token，几步即可投入使用。

**扩容轻：** 网关无状态运行，业务量增长时直接增加实例，共用 MySQL 和 Redis。

## 02 轻量，也要扛得住高并发

默认计费模式下，请求完成后先把花费写入 Redis 队列，再由后台批量提交到 MySQL。推理请求不必等待逐笔写库，同一租户下多把 Key 并发调用也能保持较高吞吐。

后台按请求 ID 去重，写库失败时整批退回重试。Key 用量、租户用量、请求日志和每日汇总一起提交，避免同一笔费用在不同统计中出现偏差。

为了看清网关本身的开销，我们把 Five API、new-api 和 LiteLLM 部署在同一台 8 核机器上，连接同一个模拟上游，使用同一套压测程序，并开启按 Key 记账。每组测试运行三轮，后台写账时间也计入总耗时。

| 网关 | 每分钟完成请求 | 满载延迟中位数 |
| --- | ---: | ---: |
| **Five API** | **4.7 万–5.3 万次** | **约 50 毫秒** |
| new-api | 4.3 万–4.5 万次 | 约 85 毫秒 |
| LiteLLM | 约 2.8 万次 | 约 115 毫秒 |

> 同机实测，Five API 吞吐比 new-api 高约 15%，约为 LiteLLM 的 1.8 倍；满载延迟同样领先。只看网关响应时，每分钟约可处理 6 万次请求。

轻量不是少做功能，而是用更短的处理链路，把每次调用更快送到上游。

## 03 企业使用，安全能力不能省

管理登录凭证和推理 Key 相互独立，上游密钥加密保存。租户只能管理自己的 Key，无法接触平台的上游地址和凭据；每把 Key 还可以设置 IP 白名单、可用模型、可用渠道和有效期。

开启请求审计后，系统按 Key 保存请求内容。私钥、AWS Access Key、GitHub Token、Slack Token 等敏感凭据会在入库前替换为脱敏标记，避免明文进入数据库和备份。

需要排查离职交接或疑似泄密时，可以选择指定 Key，让审查模型分析近期请求并生成可下载报告。

## 04 企业级，先把账号、额度和 Key 管清楚

### 发 Token，不再发一把共享 Key

平台创建租户账号，分配美元额度、可用模型，以及共享的 RPM、TPM 和并发。租户自行创建、停用和撤销 Key，并设置模型范围与 IP 白名单。各租户数据相互隔离，上游地址和密钥由平台统一保管。

Key 明文仅在创建时显示一次，撤销后历史用量继续保留，方便审计和对账。

![租户管理](../images/tenants.png)

### 预算分得清，费用看得明

租户和 Key 两层限额。额度、RPM、TPM、并发都能限，再加 5 小时、1 天、7 天的滚动限额，额度按月重置。

给团队开编码助手，可以设置为每月共享 100 美元，同时限制每 5 小时最多使用 10 美元。多个成员共享团队总额度，每把 Key 仍可设置更细的模型、渠道和调用范围。

用量按天汇总，输入、输出、缓存读取和缓存写入分别计量，方便查看费用变化和缓存带来的节省。

![成本洞察](../images/insights.png)

## 05 渠道多了，路由要稳

同一个模型可以走多条渠道，按实际服务的渠道计价，也可以给单个模型锁一口价。Key 可以限定只走某几个渠道。上游报错、超时、限流自动换渠道，流式只在首包之前换。

系统会定时检查渠道健康状态，并保留 GPT、Claude 等模型的能力检查记录，帮助平台及时发现连接异常和质量变化。

---

## 06 接入不能折腾，改个地址就能用

Five API 原样支持 OpenAI 和 Anthropic 协议，工具调用、流式事件和缓存字段随上游透传。现有应用通常只需修改 API 地址和 Token，无需重写调用逻辑。

Claude Code 2.1.197 和 Codex 0.164.0 已通过真实 DeepSeek 渠道测试。团队可以继续使用熟悉的编码工具，同时统一使用平台分配的额度、渠道和审计策略。

完整配置示例见仓库中的 `docs/CLIENTS.md`。

---

## 07 轻量开源，也应该给出完整能力

租户管理、额度与限流、精确计费、多渠道路由、IP 白名单、请求审计、凭据脱敏和 AI 泄密审查均包含在 MIT 开源版本中。

项目采用 FastAPI、Tortoise ORM、MySQL、Redis、Vue 3 和 Element Plus。网关无状态运行，多实例共用 MySQL 和 Redis，可随业务量横向扩展。

## 08 现在就可以试

### 在线体验

打开 http://192.144.177.7/ ，使用 `admin` / `admin1234` 登录。演示环境直接通过 80 端口访问，请勿填写真实的上游 Key。

### 一条命令部署

```bash
git clone https://gitee.com/dromara/five-api.git
cd five-api
./service.sh deploy
```

打开 `http://服务器IP:8080`，使用 `admin` / `admin123` 登录，首次登录后按提示修改密码。添加渠道和模型价格，再创建租户、分配额度，就可以开始发放 Token。
